# 匯出Excel格式改版 Design Spec

## 背景

`ReportExportService.Export(type, year, week, schoolIds)` 目前產出的是「匯入相容格式」——單一週次、單一 Sheet、所有分校放在一起（見 `CLAUDE.md`「匯出」章節）。但使用者提供的實際使用中的參考檔案（`C:\Leo\其他\Kuri\人數表匯入A\50\`）跟現在的匯出格式差異很大：

- **管理人員需要總表**（跨分校、依區域彙整）
- **分校人員需要自己分校的每一週資料**
- 參考檔案本身很可能就是各分校/總部長期人工或半自動維護的追蹤總表，不是系統既有的「單週快照」

## 這次範圍（已與使用者確認）

- **納入**：PH（百瀚英語，含 GEPT 英檢，因為兩者原本就合併在同一份 Excel）、PSJ（百倍速）
- **暫緩**：
  - **AS（課輔）**：參考檔案是「一校一 Sheet、整學年度所有週次垂直堆疊」的完全不同型態，範圍未定案，之後另外討論
  - **PS（百世）**：參考檔案欄位是具體班級名稱（動數學/一特/二PS特...）而非課程科系，使用者需要額外時間（預計隔天）確認這批欄位怎麼對應資料庫，這次先跳過
  - **歷史週次累積**（從每學年第一週開始逐週堆疊呈現）：使用者已確認這部分可以後續優化，**這次先做到「格式跟參考檔案一致」，不做累積歷史**

## 分區資料（已完成，套用在本機 dev DB）

`School.RegionId`/`Region` 欄位在 schema 裡本來就存在，但資料庫裡完全是空的（`Region` 表 0 筆、所有 `School.RegionId` 皆 NULL）。這次直接從參考檔案（PH「南區」/「中北區」兩個 Sheet、PSJ「北區」/「南區」兩個 Sheet 交叉驗證一致）逆向解析出實際分區名單：

- **南區**（16校，來源PH）：復興、陽明、莊敬、瑞祥、華夏、龍華、中正、正興、河堤、右昌、東安、福山、農十六、高美館、岡山、仁武
- **中北區**（10校，來源PH）：向上、大安、南京、板橋忠孝、東湖、木柵、板橋陽明、敦南、內湖、古亭
- 資料庫裡另外 8 間查無分區資料的分校（新東湖、崇明、秀朗、分校、鳳山、鳳甲、天母忠誠、許博智），依使用者指示**一律歸入南區**

已建立 `docs/superpowers/sql/2026-07-18-school-region-assignment-apply.sql`（+revert），套用在本機 dev DB 驗證：中北區10校、南區24校，與資料庫全部34間分校（扣除1筆無名稱殘留記錄）完全對上。**尚未套用到正式環境**，套用時機留待 plan 階段或使用者另行指示。

## 參考檔案結構調查（實際用 NPOI 解析比對）

### PH（`2025 07(全國人數表第50週).xlsx`）

3 個 Sheet：**南區**（分校限南區16校）、**中北區**（分校限中北區10校）、**英檢**（GEPT，不分區，全部分校）。

每個分校 Sheet 的表頭是 4 層合併儲存格結構：
- Row1：科系分組（兒美系列、國小班、國中班、Elite/SAT/英檢/國際班、高中課程、總班數、個別指導、合作開班、合計、分析 ×2＝英文/國語文各一輪）
- Row2：課程名稱（P1-初階、P2-先階...國一準特/特訓...本週英語文總人數...）
- Row3：再細分的子欄（p1/p2/p3、SAT Junior A/B、TOEFL/SSAT/PSAT、高一/高二/高三小組班）
- Row4開始：每校2列（小/三），含 `=SUM(...)` 公式（如總班數、SAT Junior 合計）

**關鍵發現**：把參考檔案的欄位順序拿去對照資料庫 `Course` 表（`Type=0`，依 `DepartmentId`+`Ordinal` 排序），**順序完全一致**——包括容易誤判為「自由格式雜項」的 GEPT「其他班系」欄位（KK音標密集班、七賢國中專班、口語班、多益班...），這些其實都是資料庫裡已存在的正常 `Course` 記錄（`DepartmentId=21`，`Ordinal 94-105`），不是需要另外維護的清單。**這代表欄位不需要手刻硬編碼清單，直接照 `Course.Ordinal`（先依 `CourseDepartment.Ordinal`，再依 `Course.Ordinal`）走訪產生表頭跟資料行即可，這一點跟 PSJ/AS 匯出目前用 `Dictionary<string,int[]>` 寫死課程Id陣列的作法（`ReportExportService.cs:29-46`）不同，PH/GEPT 這條路徑應該用「動態走訪 Course」取代寫死陣列。**

**待確認/待處理的例外**（不在單純「依Ordinal走訪」規則內）：
1. 需要「同一課程拆多子欄」的特殊表頭（SAT Junior→A/B兩欄、TOEFL/SSAT/PSAT三欄、EM1個別指導→p1/p2/p3三欄）——這些子欄在資料庫的對應方式待查（可能是`Class.Name`固定命名，或是額外的固定欄位設定）
2. Row1 最後幾欄（`126:累積詢問(填單)人數`、`127:南區總人數`、`128:6/13統資料(英文、國文)`、`129:6/13系統資料(全部)`）看起來像是人工每次填表時額外加的稽核/核對欄，不像是規律的課程資料——是否需要匯出這幾欄待使用者確認，這次先當作 **out of scope**
3. 公式儲存格（`=SUM(C5:H5)`）：匯出時要不要真的寫入 Excel 公式（存檔後 Excel 開啟會重新計算），還是直接寫入系統算好的靜態數字——兩者對使用者來說呈現結果一樣，但公式版更貼近參考檔案原始風格、也更能讓使用者事後手動微調來源數字時自動連動。**建議：先用靜態數字（系統既有 IsSum 計算已經是正確結果，公式只是原檔案人工維運時的權宜作法），除非使用者要求要能在 Excel 內即時重算。**

### PSJ（`（百倍速）人數統計表更新版115.6.13).xlsx`）

4 個 Sheet：**總表**（全部分校垂直堆疊，非分區）、**北區**（4校：南京、內湖、敦南、東湖）、**南區**（7校：東安、岡山、莊敬、高美館、瑞祥、河堤、中正，兩間分校並排同一列不同欄位區塊）、**總計**（整欄都是**跨Sheet公式**，如 `=南區!W70`，把北區+南區加總成全公司總計）。

課程欄位結構（CKC自立自學班→數學班→理化班→分析）同樣可以對照資料庫 `Course`（`Type=1`）的 `DepartmentId`+`Ordinal` 走訪產生，不需要沿用現有 `_psjCourseIds` 寫死陣列。

**「總計」Sheet 用跨Sheet公式**是本次最大的實作決策點：比照 PH 公式的建議，**建議一樣改成系統直接計算好的靜態加總值**，不寫真正的 Excel 公式，行為上等價、但少掉「NPOI 寫入公式後 Excel 開啟才會重新計算、若使用者沒有按開啟時允許計算可能顯示舊值或0」的風險。

### GEPT（PH檔案裡的「英檢」Sheet）

不分區、全部分校一個 Sheet。表頭結構相對單純（複試達陣班/三十六週攻略/二十四週攻略班/先修養成班/Cambridge/總計/分析/其他班系），同樣可以直接依 `Course.Ordinal` 走訪，已用資料庫實際課程資料逐欄核對過，順序一致。

## 設計方向（草案，待 plan 階段細化）

1. **改用「依 Course/CourseDepartment 走訪」取代硬編碼欄位清單**：PH/GEPT 這條路徑本來就是 `LoadCourses(type)` 動態查詢（`ReportExportService.cs`），這次主要是要新增「表頭要印幾層合併儲存格、哪些課程需要拆子欄」的規則描述，而不是重新設計資料來源查詢。PSJ 目前用寫死的 `_psjCourseIds`，這次順便改成一致的動態走訪方式（消滅這份寫死對照表）。
2. **依區域分 Sheet**：新增一個共用的 `GetSchoolsByRegion(type, year, week, regionName)` 或類似方法，用 `School.RegionId` 分組後各自呼叫現有的 `BuildSheetPH`/`BuildSheetPSJ`（改寫後的版本）產生對應 Sheet。
3. **PSJ「總計」Sheet**：直接對「北區+南區」兩組資料在記憶體裡加總後寫入數字（不用公式、不用跨Sheet引用）。
4. **公式一律改成靜態數字**（見上方「待確認」第3點的建議，除非使用者不同意）。
5. **本次只匯出「單一週次快照」**，比照參考檔案的分Sheet/表頭風格，但不做「整學年度累積」——之後若要做累積歷史，是另一個獨立計畫。

## 待決議事項（需要使用者或 plan 階段確認）

1. SAT Junior A/B、TOEFL/SSAT/PSAT、EM1個別指導 p1/p2/p3 這幾組「同一課程拆多子欄」的資料庫對應方式（`Class.Name`固定字串？還是需要新增欄位？）
2. PH Row1 最後4欄（累積詢問人數/南區總人數/系統資料核對欄）是否需要匯出——建議先跳過，若後續使用者需要再補
3. 公式 vs 靜態數字——本文件建議一律用靜態數字，待使用者確認同意
4. PSJ「總表」（全分校不分區堆疊）Sheet 是否要保留，還是「北區+南區」兩個分區Sheet已經足夠——參考檔案裡「總表」看起來像是舊格式/另一種彙整方式，需要使用者確認實際還有沒有在用

## Out of scope（本次不處理）

- AS（課輔）匯出格式改版——完全不同的「一校一Sheet、整年度累積」型態，另外討論
- PS（百世）匯出格式改版——欄位對應待使用者隔天確認
- 歷史週次累積呈現（從學年第一週開始逐週往下堆疊）——使用者已確認可後續優化，這次不做
- 正式環境套用分區 SQL script——已在本機 dev DB 驗證，正式環境套用時機另外決定
